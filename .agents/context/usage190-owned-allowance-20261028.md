# Directly owned allowance observer source (2026-10-28)

This proposed diagnostic is separate from the guarded Codex host and budget-owned executor. It is explicitly enabled and source-only; enabling it does not grant account access. A future authenticated observation requires a separate specific approval and a qualified artifact. The CLI does not verify that human approval; it relies on the separately approved invocation and existing filesystem and profile permissions. No remote daemon, enrollment, model, thread, login or retained native HOME is adopted.

The observer uses a fresh private tmpfs runtime destination and the existing managed access-only projection. It reads and requires an exact match against the existing shared generation fence without modifying it; a missing or mismatched projection refuses the diagnostic. The new lock serializes only upgraded writers, so an older running daemon does not participate. The foreground process must be the directly owned child, remain unreaped during the four allowed native allowance messages, and be fully stopped and reaped before output. A failed or uncertain ownership, binding, read or cleanup yields no result. Provider freshness and account binding remain Unknown.

Session and Pod values supplied to a local invocation are provenance claims, not authentication or account attribution. An explicitly approved actor, Pod and command are required for future execution; this source does not grant that authority. The generation lock is cooperative: a running older daemon does not honor it. The observer therefore only reads the shared projection fence.

Upgraded writers wait at most one second for the cooperative generation lock, checking at ten-millisecond intervals; these are source defaults, not a measured production service objective. Older daemons still do not participate. Cancellation before the native read or before final release withholds the result while preserving stop and cleanup.

If start or stop is uncertain, stop and do not retry. The named execution owner records the exact run and private lifecycle evidence. Using a separately authorized existing-host procedure, establish that the known helper and native process tree actually stopped; a missing PID alone is insufficient. Only after proving stop, clean the exact owned tmpfs observer directory with no-follow and ownership checks, without touching ordinary HOME, the shared fence or another process. If stop cannot be proven, retain the directory and report blocked custody; do not automatically delete it or restart. Future exact live approval must include this bounded recovery or a separate exact approval. This text grants no execution or recovery access.
