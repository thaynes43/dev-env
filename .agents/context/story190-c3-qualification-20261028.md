# Story 190 C3 qualification delta — source and synthetic tests

This draft is stacked on held PR #556, not a live reader, exporter integration, collector or acceptance. The existing helper now requires caller-supplied bounded observation ID, producer, incarnation, positive sequence, evidence reference and snapshot revision before opening the existing host RPC. These values are caller assertions, not authority, an independently verified producer, an account binding or proof that referenced evidence exists. No registry or identity binding is created. Invalid capture input fails before RPC.

The peer still must match the expected PID and current UID. The helper checks the initialized app-server's reported user-agent version against the existing pinned 0.160.1 convention before account reads; its source version is `app-server-reported-0.160.1`, which describes that reported value and does not assert a separately verified CLI binary. This new label is not automatically trusted or registered as actionable by the existing provider-allowance registry. Independent trusted context, source semantics and binding remain necessary; provider-observed time, freshness and account binding remain Unknown.

A synthetic Unix fake-host test exercises initialize, initialized, account/read with refresh disabled, and account/rateLimits/read with the two bounded parameters; it checks no raw fake account fields are returned, zero versus Unknown, distinct capture contexts and fail-closed context/version/peer/RPC/malformed/oversize paths. No real account, socket, provider data or credentials were read. The helper still has no production call site, and `usage-export` consumes caller-supplied JSON rather than invoking it. Any callable integration, host qualification, live proof and acceptance require separate scope and review; #556 remains held.
