# Architecture answer — reusable admin lease (source proposal)

Choose one once-approved broker-owned namespace, `dev-env-admin-issuance`, for per-grant root ServiceAccounts. The ordinary session remains in SessionNamespace with its existing identity, operator audience and Pod network. Both installed native dev-env-identity-guard and Kyverno CEL dev-env-exec-guard match dev-agents callers; the issued admin principal is outside both matches. No per-lease policy edit, param service, marker or broker policy-mutation right.

Once-only proposed activation bundle: (1) create the empty issuer namespace with standard PSA and no new exemption; (2) add a Role/RoleBinding there for only dev-env-system/dev-env-broker: serviceaccounts get/create/delete and serviceaccounts/token create; no namespace creation, pods, exec or policy writes; (3) extend native identity-guard protected target namespaces to include the issuer namespace (including Namespace objects), so baseline and ordinary grant identities cannot create/delete/recreate accounts, mint tokens, run Pods or bind RBAC there even if a broad workload role allows it; existing caller match and other Deny rules remain; (4) adjust broker-guard once to permit grant-* SAs/token requests there and root ClusterRoleBindings with exactly the same-name issuer-namespace SA subject, while retaining ordinary grants in dev-agents and disallowing other catalog roles in issuer; (5) publish the unbound catalog root role with apiGroups/resources/verbs [*] AND nonResourceURLs/verbs [*]; (6) install generated status CRD and reviewed operator/broker binary, then explicitly configure default-off admin issuer option and existing reserved decision options ONLY after Tom's specific activation approval. Kyverno match stays unchanged; ordinary identities remain inside both guards. No LAN/world/Cilium/template change; actual requester223503 already matches platform API443/6443, not a new socket proof.

Per lease: existing authenticated reserved RD2 decision and actor eligibility checks run unchanged, including requester/grant UID and fixed30m scope/deadline. Refuse disabled/unconfigured/missing issuer or mismatched approval before mint. Persist original issuer namespace, SA name and UID and root binding UID on AccessGrant; never adopt a replacement UID or migrate an existing lease after config changes. Create automount-off SA and exact root CRB only after authority; mint only for that original live UID while Active/unreleased/unexpired. Refuse less than600 seconds remaining instead of raising TTL, round down, and verify actual TokenRequest expiry is positive and no later than fixed approval deadline before installation. Install through existing requester Pod UID fence. Revocation removes original CRB first, confirms deletion with ownership/UID checks, then original SA, then token file. Persist cleanup failure and prevent reissuance once cleanup starts; expired/released leases never remint. Changed config does not retarget cleanup.

RBAC is name-based, not UID-based. UID is an issuance/lifecycle fence, not containment of trusted root. Wildcard root includes synthetic marker permissions. GET/LIST/WATCH bypass mutation admission. A principal already able to create/mint an issuer SA can recreate the name behind a leftover CRB and read Secrets; demonstrate that residual. Deleting original authority does not undo derived tokens/RBAC/Secret copies, open exec, Jobs or persistent changes. Standard PSA and all other admission still apply; envtest cannot prove live Kyverno, PSA, Cilium or cache windows. TokenRequest is not Pod-bound because requester uses a different SA.

Implement only this seam on isolated source, preserving PR801 compiler/tests unchanged as frozen evidence. Meaningful unit/envtest coverage: no authority/no mint, exact issuer/UID/decision binding, namespace/broker guard negatives, resource and nonresource root access, returned expiry, release/expiry/no remint, CRB-first cleanup and failure/config-change cases, and recreated-SA read residual.
