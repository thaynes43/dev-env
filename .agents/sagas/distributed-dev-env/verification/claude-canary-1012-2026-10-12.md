### The r1 wait held

The r1 wait reads the AgentSession with `kubectl`. All three polls failed with
`dial tcp [::1]:8080: connect: connection refused`, and the step held after 40
seconds.
The cause is the runner's `--request-timeout` flag. This pod has no kubeconfig,
so kubectl reaches the API through its in-cluster fallback. With that flag set,
kubectl skipped the fallback and dialled the empty default server,
`localhost:8080`. The coordinator reproduced it: the same command without the
flag works. The failure is observed; the client-go mechanism is inferred.

The wait makes no operator API call. It spent nothing from the Q-28 budget, and
the named and result reads stayed unspent.
