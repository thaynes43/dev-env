# Generic access: request summary foundation

Tom's 2026-10-26 direction covers individually approved internet, LAN,
Kubernetes and credential requests. Haynesnetwork services are test data, not
an access product or a blanket grant.

This source adds request identity and a digest of the complete grant spec to
existing grant views, and prints the requested network and Kubernetes scope in
the CLI. It supplies a pod-bound comparison primitive for later use. Neither a
hash nor a displayed phone answer is authentication or approval.

The decision adapter, explicit coordinator delegation, verified mobile answer
provenance, selected-field credential installer and existing-session expiry
compatibility are not implemented here. In particular, the existing broker
refuses manually approved credential grants. No new approval or installation
path is enabled by this change. Test, source, installed and usable states must
be reported separately.
