# Remote session upgrades

An automatic image, CLI or template revision change does not drain an existing user remote-control session merely because it is idle, waiting or disconnected. The controller retains the current pod and volume rather than stopping the remote agent for that update. Busy, waiting and attached protections continue to apply to other eligible sessions. If the last heartbeat stored before the stop is recorded shows the agent busy or waiting, or a client attached, the agent is not stopped. Two cases are not covered: a heartbeat stored after the stop is recorded but before the stop runs (milliseconds), and a change of state after the last stored heartbeat (heartbeats come up to 60 s apart). A drain whose stop was already recorded still finishes (DESIGN-001 5.2, 2026-11-04). Explicit owner-requested suspend, deletion and recovery use their existing paths; this update does not replace them.

If an earlier drain already recorded that the agent was stopped, the controller finishes the existing recovery path rather than leaving a stopped agent stranded. Before an automatic drain records a new stop, it rechecks the current Session and refuses remote mode. A future handoff to a newer image needs an explicitly authorized plan and independently verified continuity, including pairing and durable history; source tests alone do not prove live continuity. Publishing source does not itself install a new image or authorize a restart.
